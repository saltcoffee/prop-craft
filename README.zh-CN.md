# PropCraft

一个可视化的属性与标签整理工作台，帮你限定 Obsidian 笔记范围后合并标签、重命名字段、批量添加属性、规范化日期——零代码、零正则。

[English](README.md)

## 为什么需要 PropCraft

用了一段时间的 Obsidian 之后，仓库里总会冒出一堆“近义词”：`#阅读`、`#读书`、`#book` 其实是一回事；`作者`、`author`、`Author` 指向同一个人；日期有五六种写法。自带的属性面板一次只能改一篇笔记的一个字段，想彻底清理通常得去学脚本或配置复杂的 Linter 插件。

PropCraft 把这件事变成整理表格：打开工作台，一屏看清全库的属性和标签，拖一拖就能改好。

## 功能特性

- **精确选择笔记**：文件夹、标签和属性条件按 AND 组合，核对命中笔记并逐篇排除；切换工作台页签仍使用同一范围。
- **全库一屏掌握**：列出所有属性键和标签，显示被多少篇笔记使用、值类型和示例值。
- **一眼看出问题**：自动识别只用过一次的“孤儿属性”，以及大小写、单复数、分隔符、错别字等“疑似重复”的标签和属性。
- **拖拽即合并**：把 `#阅读` 拖到 `#读书` 上松手，先弹出预览列出所有会改动的笔记，确认后后台静默完成。
- **重命名或合并字段**：把 `作者` / `author` / `Author` 合并成一个属性，冲突值怎么保留由你决定。
- **批量添加属性**：通过向导给某个文件夹下的所有笔记加上 `status: unread` 之类的字段。
- **日期规范化**：把 `2024/1/5`、`Jan 5, 2024`、`2024年1月5日` 统一成 `2024-01-05`。
- **逐篇决定**：预览中勾选笔记并选择冲突策略；未决的有损冲突默认跳过，有歧义的日期需要确认解释。
- **有据恢复**：每批操作保存本地恢复日志，撤销前先核对；保留后续编辑，明确展示部分恢复，重试只重新预览未完成路径。
- **跟随语言**：Obsidian 用中文界面时显示中文，其它语言显示英文。

## 使用方法

1. 从侧边栏图标或命令面板打开 PropCraft 视图。
2. 在 **属性**、**标签** 或 **批量操作** 中设置共享笔记范围并核对命中结果，然后浏览属性与标签，展开 **建议清理** 查看孤儿项和疑似重复。
3. 把一个标签拖到另一个标签上，或用行内菜单重命名 / 合并属性。
4. 查看逐篇差异，取消例外笔记并处理冲突；核对实际待执行数量后应用。
5. 如果结果不对，在结果面板点 **撤销**，或到 **历史** 视图回滚。

## 兼容性与限制

需要在 **桌面版** Obsidian **1.8.7 或更高版本** 上使用，暂不支持移动端。

PropCraft 只修改你选中的元数据和标签。除正文中的内联 `#标签` 外，它不会改写笔记正文；对于属性无法解析的笔记，它会跳过而不是覆盖。属性操作保护 `tags`、`aliases`、`cssclasses` 等保留字段；标签操作会一次性修改匹配的属性标签和正文标签。设置中排除的笔记不会被写入。

YAML 注释、引号和排版可能因重新序列化而变化；未知或不安全的 YAML 会被阻止。标签匹配忽略大小写，但区分 `_` 和 `-`；筛选时包含子标签并不意味着改写整棵标签树。

开始写入前会检查历史条数和容量，包括 UTF-8 恢复材料及状态预算。达到限额后，可在历史中明确清理一条可清理的已完成记录，或调整设置。未完成与部分恢复记录受保护，不会自动淘汰历史。结果不确定的写入必须先核对才能重试。类型依赖检查会只读查看全库元数据，包括排除项，不修改这些笔记。

初始状态日志缺失时，只有所有笔记仍与日志原文一致、本次类型补充也无需回退，才能在历史中确认核对状态，解除阻塞；确认不改写业务内容。损坏的状态文件仍保持只读。

升级保留 0.1.1 历史。旧记录缺少可信操作后摘要时不能覆盖已变化的笔记，也不能恢复未记录的类型配置。新 V2 事务的恢复需要 PropCraft 0.1.2 或更高版本，降级后不能使用 V2 撤销。

## 安装

1. 打开 Obsidian「设置 → 第三方插件」。
2. 点击「浏览」，搜索 **PropCraft**。
3. 点击「安装」，然后「启用」。

## 隐私

PropCraft 完全离线运行。没有账号、没有网络请求、没有遥测，也不会访问仓库以外的文件。撤销历史保存在插件自己的本地目录中。
